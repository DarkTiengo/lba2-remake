# GPU renderer

An opt-in renderer that draws the game's 3D bodies (actors, decor objects, extras, inventory and menu models) and the exterior scenery (terrain, sea, sky) on the GPU, with smooth shading, filtered textures, per-pixel lighting on bodies and continuous distance fog. Interior rooms keep their 1997 brick art, smoothly upscaled, with actors occluded by real depth. Sprites and the 2D UI keep the original software look. Off by default: a stock run renders exactly as before.

## Using it

| Control | Where | Effect |
|---------|-------|--------|
| Renderer: GPU / Classic | Options → Display menu | Switches renderer immediately, no restart. Saved to lba2.cfg as `GpuRenderer`. |
| `gfx_gpu 0/1` | console | Same switch as the menu row. |
| GPU effects | Options → Display menu (while the renderer is GPU) | Page of on/off selectors for the effects below, applied immediately. |
| `gfx_uiscale 0/1` | console | 2D size. `1` (default) keeps the software frame at the classic height (480 to 719 lines, e.g. 960x540 for a 1920x1080 choice) so menus, text, sprites and rooms keep their authored size on screen and reach it through the pixel-art upscaler, while 3D still renders at the full resolution. `0` draws 2D natively (small UI at high resolutions). Saved as `GpuUiScale`; applied when the GPU effects page is left or at the next scene. |
| `gfx_water 0/1` | console | Modern procedural sea water. `1` (default) enables waves, palette-aware filtering, sky reflection, shore foam and contact splashes on every exterior island; `0` keeps the original sea material. Saved as `GpuWater`; GPU renderer only. |
| `gfx_lights 0/1` | console | Dynamic lights (room lamps, magic ball glow, soft light following the hero in rooms). Saved as `GpuLights`, on by default. |
| `gfx_pixelfilter 0/1` | console | xBR pixel-art filter on upscaled software pixels (bricks, sprites, UI). Saved as `GpuPixelFilter`, on by default. |
| `gfx_deband 0/1` | console | In-between colours on the palette's ramps for upscaled software pixels. Saved as `GpuDeband`, on by default. |
| `gfx_lamps 0/1` | console | Lamp globes on 3D models (street lamps) cast light. Saved as `GpuLamps`, on by default. |
| `gfx_lowpower 0/1` | console | The graphics card: 0 high-performance (default), 1 power-saving (integrated). Saved as `GpuLowPower`; switching recreates the renderer on the chosen card. |
| `gfx_smoothterrain 0/1` | console | Terrain cells near the camera curved into smooth hills and valleys. Saved as `GpuSmoothTerrain`, on by default. |
| `gfx_sky 0/1` | console | Procedural sky over every exterior: gradient, sun, drifting clouds, stars, a sea of clouds under islands above them. Saved as `GpuSky`, on by default. |
| `gfx_storm 0/1` | console | Modern rain and lightning: layered rain with splashes, bolts in the sky, flashes lighting the scene. Saved as `GpuStorm`, on by default; `0` keeps the rain lines and the lightning palette. `lightning` strikes a bolt. |
| `gfx_sunlight 0/1` | console | Global light: sun shadows, sky fill and rim light on bodies, sun/sky grading, sun bloom, outdoor ambient occlusion. Saved as `GpuSunlight`, on by default. |
| `gfx_raytrace 0/1` | console | Shadows ray traced outdoors through every body and the terrain, from the sun (with `gfx_sunlight`) and the lights. Saved as `GpuRayTrace`, on by default. |
| `gfx_shadows 0/1` | console | Soft shadows, also cast away from lamps, fire and the magic ball. Saved as `GpuShadows`, on by default; `0` keeps the original shadow. |
| `gfx_fire 0/1` | console | Procedural flames and flickering firelight on the game's animated fire textures. Saved as `GpuFire`, on by default. |
| `gfx_specular 0/1` | console | Specular highlights on 3D models. Saved as `GpuSpecular`, on by default. |
| `LBA2_GPU=1` / `LBA2_GPU=0` | environment | Forces the choice for this run only, without changing the saved one. With `1` the window is created with the GPU renderer from the first frame. |
| `LBA2_GPU_DEBUG=1` | environment | Tints every pixel the GPU supplies green, to check coverage. `2` shows the GPU image alone (magenta where it drew nothing), without the software frame. |
| `LBA2_GPU_CAPTURE=<file.bmp>` | environment | Writes the last presented frame to disk (GPU composite and menu overlay included, with either renderer); add `LBA2_CAPTURE_MENU=1` to keep only frames with the modern menu up. `--screenshot` saves the software frame, so this is how to capture the GPU look. |
| `LBA2_GPU_STATS=1` | environment | Logs the CPU cost of each present (tag scan, uploads, render) every 300 presents. |

If the GPU renderer cannot be created (no Vulkan device, headless run), the window keeps the classic renderer and logs a warning; the saved choice is left as the player set it.

```bash
LBA2_GPU=1 ./lba2cc
LBA2_GPU=1 LBA2_GPU_CAPTURE=gpu.bmp ./lba2cc --exec "cube 42" --tick 200 --exit
```

It needs SDL 3.4 or newer at build time; a build against an older SDL compiles the layer out and `LBA2_GPU` does nothing. Shaders are SPIR-V only for now, so the layer runs where SDL GPU uses Vulkan (Linux, Windows, Android). Metal and Direct3D builds fall back to the software look.

## How it works

The software rasterizer still draws every body into `Log`. That keeps every visibility rule of the original intact: bricks redrawn over actors in interiors, the exterior z-buffer against the terrain, menus and text on top. The GPU only replaces the colour of pixels a body owns.

1. **Capture** ([LIB386/OBJECT/AFF_GPU.CPP](../LIB386/OBJECT/AFF_GPU.CPP), [SOURCES/3DEXT/TERRAIN_GPU.CPP](../SOURCES/3DEXT/TERRAIN_GPU.CPP)). While `ObjectDisplay` / `BodyDisplay` rasterize a body, the capture records its entities as GPU vertices: positions projected on the CPU with the engine's own perspective or isometric formulas (so silhouettes match), view-space normals, palette colour, texture coordinates. Transparent, pattern and table fills and lines are recorded as "pass" geometry, which makes their pixels keep the software colour. The exterior scenery is captured next to its software fills in `TERRAIN.CPP` and `DRAWSKY.CPP`: every terrain cell of the current and horizon cubes with its authored vertex intensities, colour bank, Gouraud table and texture coordinates, and the sea and sky planes in camera space. Interior rooms are captured in `AffGrille` ([SOURCES/GRILLE.CPP](../SOURCES/GRILLE.CPP), with the GPU brick layer in [SOURCES/GRILLE_GPU.CPP](../SOURCES/GRILLE_GPU.CPP)): every drawn brick becomes a quad over its sprite, whose coverage comes from a brick atlas and whose depth the fragment shader computes per pixel by casting the isometric view ray through the brick's grid cell (the same depth formula as isometric bodies). Bricks overwrite each other in software order, as their sprites overlap by design, and only their depth is kept for actors to test against; `DrawOverBrick`'s masked re-blits carry the bricks' tags along.
2. **Tagging** ([LIB386/SVGA/GPUOBJ.CPP](../LIB386/SVGA/GPUOBJ.CPP)). Every pixel the body changes in `Log` gets the draw's id and the palette index it wrote. The exterior scenery pass (`AffGrilleExt`) is one group: all its draws share one id and the frame is diffed once, after the pass, against the cleared frame it started from. Tag planes follow the pixels when `CopyScreen`, `CopyBlock` or the dirty-box restore copy between `Log`, `Screen` and full-frame buffers (`ScreenAux`, `BufSpeak`), so a body baked into the background, or a scene kept behind a menu, keeps its id.
3. **Present** ([LIB386/SYSTEM/GPURENDER.CPP](../LIB386/SYSTEM/GPURENDER.CPP)). The GPU targets match the frame's size on screen (up to 3840x2160), not the software frame's, so models render at the window's resolution: a 1920x1080 frame on a 4K window gets 4K models. A pixel is live when its tag is set and `Log` still holds the index the body wrote. Every present re-renders each draw that still has a live pixel, with the current palette, fog remap, CLUT and texture pages, into a colour target and an id target. Drawing order follows the software painter's order through depth slices; consecutive z-buffered bodies (exterior decors, drawn front to back) share a slice and let depth decide.
   Draws opened during the scene part of `AffScene` (exterior scenery or interior bricks, actors, extras) are scene draws: they share the back half of the depth range and depth-test each other for real, while menu and inventory models keep the draw-order slices in front of them.
4. **Composite** ([LIB386/SYSTEM/SHADERS/COMPOSITE.frag](../LIB386/SYSTEM/SHADERS/COMPOSITE.frag)). The SDL renderer draws the software frame through a custom fragment shader: where the pixel's tag equals the id the GPU wrote, or where both are scene ids (the GPU's depth then picks the surface, at the GPU's resolution), the GPU colour replaces it, except where the nearest surface is an interior brick, which shows the software frame; anywhere else the software colour stays. Wherever the frame is shown larger than its pixels, software pixels (bricks, sprites, UI) go through a pixel-art upscaler (xBR level 2 with blended edges) and a debanding pass that averages neighbours of nearly the same colour, filling the palette's 16-step ramps with in-between colours without crossing edges. Scene pixels are then multiplied by the dynamic light the GPU wrote to a third target.

Dynamic lights ([SOURCES/OBJECT.CPP](../SOURCES/OBJECT.CPP) `AffScene`, `AffGpu_AddWorldLight`) are up to 16 point lights set each scene frame in world coordinates and moved into the space the capture stores positions in (camera-relative world in rooms, view space outdoors). Bodies take them through their normals, terrain and bricks omnidirectionally at their surface point (bricks use the point their depth ray found). The original data has no light sources. Room lamps are listed by hand in [SOURCES/GRILLE_GPU.CPP](../SOURCES/GRILLE_GPU.CPP) (`kLampBricks`) by their brick number in `BKG.HQR`, found by checking every room that uses each candidate: lamp shades, wall sconces, globe lamps, glowing fixtures, crystal lamps, candles. `LoadUsedBrick` maps the room's sprites back to those numbers; each drawn lamp (stacked lamp bricks merged into one) lights with the average colour of its brightest pixels in the room's palette, nearest to the camera first. The magic ball and a soft light over the hero in rooms emit too; the ball's light stops when it bursts (the extra that flies home is an invisible seeker, `EXTRA_SEARCH_OBJ`).

**Fire.** The object texture page declares animated fire regions (`ScanTextureAnimation`, 32x32 each, rewritten by `Do_Fire` every frame); the page and regions are handed to the GPU layer (`GpuObj_SetFireRects`). With `gfx_fire` on (Display > GPU effects > Modern fire, `GpuFire`), fragments of textured polygons that sample a fire region draw procedural flames instead (layered noise rising over time, a white-yellow root through orange to red ragged tips, unshaded), and every live body with such polygons casts a warm flickering light at their centre (`T_GPUOBJ_DRAW::HasFire`, added by the presenter each present, so bodies baked into a room's background keep lighting it). Fire made of many small bodies close together (a dragon's breath) casts one light. Braziers, fire breath and the laser barriers that reuse the fire texture all take it.

**Modern water.** With `gfx_water` on (Display > GPU effects > Modern water, `GpuWater`), every exterior island's sea tile captured by [SOURCES/3DEXT/TERRAIN_GPU.CPP](../SOURCES/3DEXT/TERRAIN_GPU.CPP) is subdivided into an 8 × 8 mesh. Its broad waves displace those vertices before homogeneous projection and provide the surface normal; the material adds finer procedural detail, palette-aware bilinear samples and a view-dependent sky reflection. The wave phase follows island-global position, so it remains continuous across cubes and stable while the camera moves, and the material receives the scene's directional light. `gfx_water 0` bypasses that mesh and keeps the original two-triangle sea capture. The original shoreline animation is preserved separately: terrain polygons with `CodeJeu` 12 (`CJ_FOOT_WATER`) or 15 (`CJ_ANIMATED_WATER`) keep their pinned, authored coastline geometry and texture UVs, while the original 32 × 32 frame strips continue updating `GroundTexture` every 250 ms. Those polygons are tagged as water for the boundary/foam pass, but their live indexed page remains the source of colour. This is render classification only; terrain collision, movement and drowning rules remain unchanged.

The object shader marks water and sky pixels in the light target. [LIB386/SYSTEM/SHADERS/COMPOSITE.frag](../LIB386/SYSTEM/SHADERS/COMPOSITE.frag) searches outward from visible water pixels for terrain or 3D geometry and draws animated breaking foam along that real screen-space boundary. Foam can cross onto non-water geometry only when its world-up height and scene depth both match the sea edge, so a dry hero or elevated/foreground object beside the coast does not acquire a halo. A separate sky marker prevents the sea horizon from being mistaken for a coast. This covers beaches, cliffs, harbour walls, piers and objects standing at the waterline without scene-specific coordinates.

For a visual contact check, run the SDL/smacker build with `LBA2_GPU=1` and `LBA2_GPU_CAPTURE` set, drive a known exterior save with `--teleport` or `--exec`, and save a fixed-timestep frame with `--dump-state`. Compare a frame with the hero above `Y_SEA` against one with the feet crossing `Y_SEA`: the first must have neither side of the shoreline foam boundary on the hero, while the second may foam only at the matching-height contact. Repeat at a second resolution and with one camera move; the contact must stay attached to geometry rather than to the projected screen position. The control harness details are in [docs/CONTROL.md](CONTROL.md).

Actors crossing `CJ_WATER`, `CJ_FOOT_WATER` or `CJ_ANIMATED_WATER`, and flying extras such as hooks, fish and thrown objects, call `Water_Impact` in [SOURCES/WATER.CPP](../SOURCES/WATER.CPP). Exterior actors also test the physical `Y_SEA` crossing, so a jump reacts at the visible surface even when the underlying brick code changes early or late; the first drowning frame is a final fallback for unusual deep-water bricks. The harbour fisher is a special authored case: rod, line and fish are part of one animated body rather than a projectile, so its catch frame searches outward for the nearest coded water point and emits a strong extraction contact followed by two smaller patches of churn. Up to eight short-lived contacts add expanding world-space rings, a low frothy crown, a water column and ballistic droplets. Entry strength follows vertical speed and the hero's accumulated fall height; leaving the water produces a smaller contact. The event clock follows game time, so paused menus do not advance the animation, and island ownership prevents a recent splash leaking across a scene change.

When the exterior rain system is visibly active, the water material adds faster long swells, small short-lived world-anchored rain rings, and stronger surface motion. The rings use jittered centres, independent phases and footprint fading, so they remain fine drops rather than a circular lattice. The composite's ground-splash pass skips marked sea pixels, leaving sea impacts to this material; fine rain detail remains shader-based while the broad silhouette is carried by the displaced mesh. Breakers travel faster and reach farther across both sides of detected beach, rock and pier boundaries; calm scenes keep the narrower motion. The sky marker still excludes the horizon from boundary foam, and refined marker crossings keep the contact attached to the actual quay or shore surface.

**Soft shadows.** With `gfx_shadows` on (Display > GPU effects > Lighting and shadows > Soft shadows, `GpuShadows`), `DrawShadow` ([SOURCES/BEZIER.CPP](../SOURCES/BEZIER.CPP)) hands the shadow the game projected (its four ground points from `ProjectShadow`/`ProjectShadowExt`, the ground's altitude, and its caster, found by `AfficheShadow` as the object standing at the shadow's X, Z) to `AffGpu_Shadow` instead of darkening the frame. The shadow becomes an 8 × 8 grid lying on the ground (a grid, because depth linear in view depth is interpolated linearly on screen and a large quad would sink under the ground) and is drawn after the scene into a fourth target, depth-tested so walls and bodies in front hide it; overlapping shadows keep the darkest. Its red channel is a soft contact shadow, fainter and wider the higher the caster jumps. Besides, every shadow follows its caster's shape: while the frame is captured `AffGpu_End` keeps each body's triangles in scene space, and once every body is in (`AffGpu_BuildShadows`, from `AffScene`) the body standing at the shadow's caster is flattened on the ground plane, away from the sun (with `gfx_sunlight`) and away from the two lights reaching it the most (the scene's lights, lamps and fires on bodies; not a light the body carries, like the light over the hero in rooms), fading with the distance from its feet (`GPUOBJ_MODE_SILHOUETTE`). A sun silhouette adds to the red channel; a light's writes, in the green channel, the share of the dynamic light that light brings there, which the body takes away. Silhouettes are drawn sharp and the composite reads the target through a small blur, so their edges come out soft. The composite darkens the frame by the red channel, also where the room's frame is untouched but the GPU knows the surface, and removes the green share of the dynamic light. `LBA2_GPU_DEBUG=3` shows the target: grey for the contact shadow, red for blocked light.

**Global light.** With `gfx_sunlight` on (Display > GPU effects > Lighting and shadows > Global light, `GpuSunlight`), the light that shades bodies (`CameraXLight`, the sun outdoors, the room's light indoors) is treated like the lamps. `UpdateSceneLight` in [LIB386/OBJECT/AFF_GPU.CPP](../LIB386/OBJECT/AFF_GPU.CPP) records its direction and the world's up in scene space while the frame is captured; the presenter judges day or night from the palette's brightness and appends direction, up and colours to the lights uniform. Soft shadows then also reach away from the sun, in the body's shape (clear under a daylight sky, faint at night and in rooms). Shaded bodies get a sky fill on the side turned up but away from the sun, which the palette ramp leaves flat dark, a little ground bounce, and a sun-coloured rim when the sun is behind them. The composite grades scene surfaces (lit ones toward a warm sun, shaded ones toward the sky's blue; silver and deep blue by moonlight), lets sunlit highlights bloom softly through the lamps' glow, and darkens creases by ambient occlusion: the view distance is packed in the shadow target's blue and alpha (16 bits), and each pair of opposite neighbours predicts where a flat surface through them would put the pixel (harmonic in perspective); lying behind it is a crease. Within one draw only sharp corners count, so the low-poly terrain's gentle folds stay smooth; large distance jumps (other objects, horizon cubes drawn from a shifted camera) are ignored; rooms get none, their brick furniture's depth being its brick's box. `LBA2_GPU_DEBUG=5` shows the occlusion.

**Ray-traced shadows.** With `gfx_raytrace` on (Display > GPU effects > Lighting and shadows > Ray tracing, `GpuRayTrace`) in an exterior, shadows are traced through everything the present keeps alive: houses, trees, the ship, decor, characters and the terrain itself, so hills shade valleys, the pier's walls shade the sea, and every body shades the ground, the sea and each other, from the sun and from the lights (lamps, fires, the magic ball). No hardware ray tracing is involved (SDL's GPU API exposes none): the presenter gathers the live draws' triangles (not sky, sea, bricks, sphere impostors or lamp glass, which the light shines from; their vertices hold scene-space positions) and builds a bounding volume hierarchy on the CPU each present ([LIB386/SVGA/GPUBVH.CPP](../LIB386/SVGA/GPUBVH.CPP), median split on the widest axis, four triangles a leaf; `test_gpu_bvh` checks it against testing every triangle), uploaded to two storage buffers the composite reads. There each pixel with a surface turns its screen position and packed view distance back into a scene point (`XCentre`, `YCentre`, `FRatioX`, `FRatioY`) and a normal from its neighbours on the same surface, then traces from just above it: four rays over the sun's disc, turned per pixel, for a soft penumbra (not on a surface turned away from the sun, which its own shading already darkens), and one ray toward each of the eight lights nearest the camera, stopping 450 units short of the light so its lamp's frame does not shade it; the share of the dynamic light blocked is taken away, weighed as the shaders weigh the lights. Silhouettes are then not drawn. The hierarchy holds up to 131072 triangles; with the terrain in it, building it costs about 3 ms of CPU a present on the Desert Island dock and in the Citadel square. `LBA2_GPU_DEBUG=6` shows the traced shadows alone: grey the sun's, red the lights'.

**Performance.** The composite's costliest work, the ray-traced sun and light shadows and the ambient occlusion, runs at half resolution: a pass built from the same shader source with `HALF_PASS` (`COMPOSITE_HALF.frag.spv.h`, drawn by `FULLSCREEN.vert`) writes them into a quarter-size target before the composite, which reads them back through a depth-aware upsample (the four half texels around a pixel weighed by how close their surface's distance is to its own, so shadows do not bleed across edges). The ray-tracing hierarchy is built on a worker thread while the present uploads vertices and tags, and the build itself sorts triangles along a Morton curve with a radix sort and merges boxes bottom-up (about 0.8 ms for 15000 triangles, from 3 ms). On Desert Island's dunes at 1920×1080 on an RTX 4060 laptop, a frame went from 22 ms to about 15.5 ms. The game's logic and the software rasterizer stay on one thread: the simulation must stay deterministic and the painter's order is strict.

**Smooth terrain.** With `gfx_smoothterrain` on (Display > GPU effects > Smooth terrain, `GpuSmoothTerrain`) the exterior terrain's land triangles within 26000 units of the camera are cut into sixteen smaller ones lying on a curved surface ([SOURCES/3DEXT/TERRAIN_GPU.CPP](../SOURCES/3DEXT/TERRAIN_GPU.CPP)): each point is its original triangle's plane moved toward a Catmull-Rom surface through the cube's height map (which passes through every original height), upward only and by at most 220 units, so hills and crests round off without a fold ever sinking to open a gap onto what lies behind, and the ground the game collides with stays within that distance of what is drawn. Every point depends only on where it lies, so neighbouring triangles meet exactly: the curve fades out with the distance (18000 to 26000 units), at the sea's level, on the cube's border, and toward the corners of triangles drawn flat (water, far cells), which are only known once the whole cube is captured, so land triangles are held until `TerrainGpu_End`. The silhouette against the sky stays the classic one (the software decides what shows), and where a curved crest lies just below it the composite keeps the software's terrain pixel rather than the sky. Shadow rays keep tracing the original terrain, on or below the curved one: the small triangles are flagged (`GPUOBJ_FLAG_DETAIL`) and the first of each carries the original corners for the hierarchy, sixteen times fewer triangles to build (about 2 ms of CPU a present on Desert Island's dunes).

**Modern sky.** With `gfx_sky` on (Display > GPU effects > Lighting and shadows > Modern sky, `GpuSky`) the composite draws the sky of every exterior itself ([LIB386/SVGA/GPUSKY.CPP](../LIB386/SVGA/GPUSKY.CPP) holds the scene's state). A pixel is sky when it shows the island's textured cloud ceiling (the GPU's sky marker) or, inside the scene's window and where no GPU surface lies, the fog-coloured background. For each such pixel the view ray is rebuilt from the projection and turned into the world's frame (`GpuObjWorldX`, the world up, `GpuObjWorldZ`, recorded with the scene light), and the sky along it is: the island's fog colour as a pale haze on the horizon deepening toward a zenith (darker at night, judged from the palette), the sun's disc and glow, clouds on a dome anchored to the world and drifting with the wind (value-noise fbm with quintic interpolation, lit on the sun's side and darker underneath, thinning into the haze, fully closed in Citadel Island's storm), and stars in the gaps at night. The islands are flat and bounded, so the background seen above the land lies a little below the true horizon; the sky's horizon is lowered to match. On an island above the clouds (the cloud ceiling below the camera, `Sky_Y < CameraY`) the rays below the horizon show a sea of clouds with billowing, sunlit tops instead, laid on the ceiling's plane and anchored to the world (`GpuSky_SetCamera`), so looking straight down (Zeelich's upper cloud layers) keeps their size and they stay put as the camera moves. Zeelich (islands 4 and on) is cloudier than Twinsun. Islands 5, 6, 7 and 11 lie at the bottom of Zeelich's gas: a heavy cover closes their whole sky, lilac-grey gas rolling and churning slowly with darker folds and paler swells (domain-warped noise), its ragged underside over a band of the island's glowing haze on the horizon, as the original ceiling texture shows it. The Emerald Moon (island 3) floats in space: its sky is black with a dense star field and a band of the galaxy, and Twinsun hangs close and large in it as the game has it: a sun over each pole warms the two hemispheres (oceans, islands, clouds) and lights them from both sides, the equator between them is a frozen, mountainous band, and a blue atmosphere glows past its limb; the planet is placed once per cube high in the scene's window, right of its middle, and stays put in the world. Scene surfaces fade into the sky rather than into the fog colour: past the island's fog start the composite blends each toward the sky's gradient along its own ray (aerial perspective, without clouds, which lie beyond the land), and what the fog has all but swallowed becomes the sky itself, so far land and the sea meet the sky without a seam. A body reaching into the cloud ceiling stays hidden by it, as in the classic view. Rain and lightning draw over it.

**Rain and lightning.** With `gfx_storm` on (Display > GPU effects > Lighting and shadows > Rain and lightning, `GpuStorm`) the GPU renderer draws the storm of Citadel Island's opening chapters ([LIB386/SVGA/GPUSTORM.CPP](../LIB386/SVGA/GPUSTORM.CPP)): `AffScene` skips the software rain lines (`AffRain`; `GereRain` still runs) and the INCRUST_ECLAIR incrust no longer swaps in the lightning palette. The composite draws the rain in three layers at increasing depth (near, mid, far), slanted by the wind and blurred along their fall, each hidden behind a nearer surface by the packed view distance, and rings spreading where drops hit ground turned up (a grid on the ground plane, two drops a cell); only on the scene's own pixels, not the HUD or the cinema bars. Lightning strikes while a scripted lightning (`LM_ECLAIR`) lasts, every 0.7 to 2.3 s, and on its own during the rain every 6 to 16 s, from a generator of its own (the game's random sequence is untouched). A strike has a flash with the return strokes that make lightning flicker; outdoors it comes from a direction above the horizon, lights surfaces by how they face it and, when rays are traced, casts shadows from it; in rooms it brightens everything more softly, as through the windows. In the sky (the software sky inside the scene's window, or land more than 45000 units away) the clouds around the strike light up and the bolt is drawn for its first third of a second: a jagged channel from the top of the frame with three branches, a white core and a blue glow, hidden by the land in front. Purely visual: `lightning` on the console strikes one.

**Lamps on models.** Island decor models that are lamps are listed by island and model number (`kLampModels` in [SOURCES/3DEXT/DECORS.CPP](../SOURCES/3DEXT/DECORS.CPP), found by looking: Citadel Island's street lamp (0:26), Desert Island's lighthouse (2:0), the Emerald Moon's ring light, square light and lanterns (3:19, 3:27, 3:29) and a dome lamp (6:24), found by rendering every candidate model with bright warm unshaded glass alone). While one is drawn, `GpuObjLampModel` tells the capture, which marks its pale, bright, warm glass (judged in the scene palette, since decors are captured while the video palette still fades in) emissive: the shader lights it from inside and the composite draws a bloom halo around it, and the body casts a steady light in the glass colour from its centre, with a larger radius in exterior scenes. With `gfx_lamps` on (Display > GPU effects > Lighting and shadows > Lamps on models, `GpuLamps`). Lamps whose glass is not pale and warm (the curved Zeelich street lamps) are not listed.

**Flames.** A body whose fire-textured polygons stand up in the world (vertical extent against horizontal, and not mostly slivers, which excludes the laser barriers sharing the texture) records their screen box; the presenter merges overlapping boxes and the composite draws a volumetric flame over each, above the original polygons: taller than them, swaying with height, turbulent layered noise, a white-yellow core through orange to red, transparent ragged edges. The polygons keep the procedural fire texture as the flame's glowing bed.

**Glow.** Emissive surfaces (fire flames, lamp glass) write their strength to the light target's alpha; the composite adds a soft halo from three rings of taps around each pixel, over GPU and software pixels alike, so flames lose their hard polygon edges and lamps read as light sources.

**Magic ball.** While the ball flies, its sprite's core is replaced by a lit glossy sphere (`GPUOBJ_MODE_ORB`, `AffGpu_OrbBegin/End` around the sprite draw in `AffOneObject`): tinted from the sprite's own saturated pixels, centred on what the sprite drew, with a hot core, a coloured rim and a sharp highlight. It uses exact id matching rather than scene depth, so the sprite's halo keeps its software pixels.

**2D scale.** With `gfx_uiscale` on, `Res_FrameDivisor` ([SOURCES/RES_SWITCH.CPP](../SOURCES/RES_SWITCH.CPP)) divides the chosen resolution down to the classic height whenever the GPU renderer is on (not headless). The GPU targets still follow the window and the chosen size, so bodies, terrain, sea and sky and the depth of bricks are rendered at full resolution, and everything drawn in 2D is magnified by the composite's xBR filter.

Colours still come from the original data. Terrain keeps its authored per-vertex intensities, interpolated per pixel through the unfogged Gouraud table rows; its 16 fog steps become a continuous fade to the fog colour by view depth. The shade index a Gouraud or flat polygon would use is computed per pixel from interpolated normals, then blended between neighbouring entries of its 16-step palette ramp (or CLUT rows for textured polygons), so banding and dithering disappear without changing the palette. A specular term is added on top. Textures are filtered bilinearly in palette space.

Re-rendering live draws each present, rather than keeping their colour, is what lets palette fades and flashes reach GPU pixels: decor objects are drawn once when a scene is entered, often while the palette is still faded to black.

## Limits and known gaps

- Pixels a body writes with the same palette index that was already there are not tagged, and keep the software colour.
- Where another sprite or text later writes exactly the index a body had written, that pixel shows the body's GPU colour.
- A body switching texture page or CLUT mid-way keeps the software colour for the rest of its polygons.
- Tags are scanned and uploaded over the box that holds them each present: cheap in interiors, about 2 ms at 1280x960 in a full exterior view.
- Where the GPU renders above the software frame's resolution, edges against software pixels (sprites, shadows, rain, interior bricks) still follow the software frame's pixels; edges between scene surfaces in exteriors do not.
- Sprites, particles, rain and shadows are still software, and so is the interior brick colour (upscaled with xBR).
- Modern water replaces exterior sea planes; water represented by authored bricks inside isometric rooms keeps the original room art.
- Only the lamps in `kLampBricks` emit: lamps modelled as 3D objects, torches and fires in exteriors do not. A lamp brick just off screen does not light the edge of the view.
- `gfx_gpu` or `gfx_uiscale` typed in the console resize the frame at the next scene; the menu applies them at once.
- A brick's depth is its whole grid cell, as the software occlusion rules assume: furniture thinner than a cell hides an actor inside the same cell.

## Changing the shaders

The GLSL sources live in `LIB386/SYSTEM/SHADERS/`. The build embeds the committed `*.spv.h` headers, so no shader compiler is needed to build. After editing a shader, regenerate them with [scripts/dev/build-gpu-shaders.sh](../scripts/dev/build-gpu-shaders.sh) (needs `glslc` from shaderc or the Vulkan SDK, and `xxd`).
